오늘 하는 것과 하지 않는 것

오늘 하는 것
  • 내 업무 중 작은 한 단계 고르기
  • 그 단계에 필요한 데이터 정리하기
  • AI에게 알려줄 기준 문서 만들기
  • 단일 에이전트 한 번 작동시켜보기
  • 반복할 수 있는 작업인지 판단하기
오늘 하지 않는 것
  • 전체 업무 자동화
  • 멀티 에이전트 구성
  • 웹 서비스 / DB / API / MCP 구축
  • 완성도 높은 시스템 제작
  • 지난주 과제 완성
오늘 목표는 완벽한 시스템이 아닙니다. AI에게 맡길 첫 번째 업무를 하나 골라서 한 번 돌려보는 것, 그게 전부입니다.

왜 문제를 좁혀야 하는가

비유로 이해하기
에이전트 만들기는 큰 부서 하나를 세우는 일이 아닙니다.
신입 한 명에게 첫 업무 지시서를 쓰는 것에 가깝습니다.

"정산 업무 전체 다 해줘"라고 하면 어렵습니다.
대신 "이 엑셀에서 이상한 금액만 찾아서 표시해줘"라고 하면 훨씬 잘 작동합니다.

오늘은 AI에게 맡길 첫 번째 업무 지시서를 만드는 날입니다.
처음부터 크게 하면 어려운 이유설명
필요한 데이터가 많아짐업무 전체를 다루려면 자료 준비만도 한참 걸림
판단 기준이 복잡해짐단계마다 다른 기준이 필요해서 AI에게 설명하기 어려워짐
성공 기준이 흐려짐무엇이 잘 된 건지 판단하기 어려워짐
오늘 결과를 못 봄실습 시간 안에 작동 여부를 확인하기 힘듦

"좁힌다"는 게 구체적으로 어떤 뜻인가

"문제를 좁혀라"고 하면 막연하게 들립니다. 좁히는 행위를 한 문장으로 정리하면 이렇습니다.

Before / After 사례

사례 1. 재무·정산 업무

Before — 너무 넓다
재무 업무 전체를 자동화하고 싶다
  • 데이터 확인
  • 금액 검증
  • 이상값 탐지
  • 보고서 작성
  • 승인 요청
After — 좁혔다
엑셀에서 이상값을 찾아 요약 메모를 만드는 에이전트
  • 입력: 엑셀 파일 (CSV 변환)
  • 출력: 이상값 목록 + 한 줄 요약
  • 매주 반복 → 반복성 충족
  • 기준 명확 → 명확성 충족

사례 2. 연구·정책 리서치

Before — 너무 넓다
정책 동향 리서치 보고서를 자동화하고 싶다
  • 검색
  • 자료 선별
  • 요약
  • 비교
  • 시사점 작성
After — 좁혔다
뉴스 기사 5건을 같은 기준으로 요약하고 공통 키워드를 뽑는 에이전트
  • 입력: 기사 본문 텍스트
  • 출력: 기사별 핵심 요약 + 공통 키워드
  • 보고서 쓸 때마다 반복
  • 형식 고정 가능

사례 3. 행사·교육 운영

Before — 너무 넓다
교육 운영 전체를 자동화하고 싶다
  • 신청자 확인
  • 안내 메일 작성
  • 참석자 명단 정리
  • 만족도 조사 정리
  • 결과 보고서 작성
After — 좁혔다
참석자 명단 CSV를 기준으로 안내 메일 초안을 만드는 에이전트
  • 입력: 참석자 명단 CSV + 교육 일정
  • 출력: 안내 메일 초안 + 누락 정보 체크리스트
  • 행사마다 반복
  • 메일 형식 고정 가능

사례 4. 보고서 작성

Before — 너무 넓다
기술동향 보고서 전체를 자동화하고 싶다
  • 자료 수집
  • 분석 및 정리
  • 초안 작성
  • 검토 및 수정
  • 최종 편집
After — 좁혔다
논문·뉴스 3건을 요약해서 보고서 서두 단락으로 만드는 에이전트
  • 입력: PDF 또는 기사 본문 텍스트
  • 출력: 핵심 내용 3줄 + 시사점 1줄
  • 보고서 쓸 때마다 반복
  • 출력 형식 고정

실습 — 내 과제 좁히기 8분

지금 할 일
  1. 내 과제 정의서를 연다.
  2. 업무 단계를 3~5개로 나눠본다.
  3. 가장 자주 반복되는 단계를 하나 고른다.
  4. 그 단계의 입력 자료와 출력 결과물을 적는다.
  5. 오늘 만들 에이전트 이름을 한 문장으로 정한다.

데이터 준비 전 확인사항

데이터가 걱정될 때 — 원본을 그대로 넣지 않아도 됩니다. 아래 세 가지 방법 중 하나를 선택하면 됩니다.
방법설명
1. 비식별화이름, 기관명, 연락처, 담당자명을 지운다
2. 더미 데이터실제 금액, 실제 이름 대신 예시값으로 바꾼다
3. 구조만 가져오기원본 내용은 빼고, 표의 컬럼명·문서 형식만 가져온다
상황처리 방법
개인정보가 있다삭제 또는 가명 처리
내부 기관명이 있다"A기관", "B부서"처럼 변경
금액·계약 정보가 있다예시 금액으로 변경
문서 구조만 필요하다내용은 지우고 제목·항목만 남김
공개 자료다출처와 함께 사용 가능
처음엔 3~5개만 넣으세요. 데이터를 많이 넣는다고 결과가 좋아지지 않습니다. 처음부터 50개를 넣으면 결과가 왜 틀렸는지 확인하기 어렵습니다. 작게 넣고 결과가 괜찮으면 조금씩 늘리는 방식으로 합니다.

1
프로젝트 폴더 만들기

Finder(Mac) 또는 파일 탐색기(Windows)에서 적당한 위치에 새 폴더를 만듭니다. 바탕화면보다는 문서(Documents) 폴더 안을 권장합니다. 폴더 이름은 한글 OK, 띄어쓰기 대신 _ 사용을 권장합니다.

기술동향_에이전트   ← 예시 이름
2
VS Code에서 폴더 열기

두 가지 방법 중 하나를 선택합니다.

  • 메뉴로: VS Code 상단 File → Open Folder → 만든 폴더 선택
  • 드래그로: Finder에서 폴더를 VS Code 아이콘 위로 드래그
열리면 왼쪽 탐색기 패널에 폴더 이름이 표시됩니다. 이 패널이 안 보이면 Ctrl+Shift+E를 누르세요.
3
폴더 구조 만들기

탐색기 패널에서 두 가지를 만듭니다.

  • data 폴더: 탐색기 패널 상단 폴더 아이콘 클릭 → data 입력 → Enter
  • 기준문서.md: 파일 아이콘 클릭 → 기준문서.md 입력 → Enter
기술동향_에이전트/
├── data/
└── 기준문서.md
4
데이터 파일 넣기

에이전트가 읽을 파일을 data/ 폴더에 복사합니다. PDF는 텍스트로 변환이 필요합니다.

  • PDF를 Chrome으로 열기 → Ctrl+A → Ctrl+C
  • VS Code에서 새 파일(예: paper_01.txt) 만들고 붙여넣기 → data/ 안에 저장
처음엔 3~5개만 넣으세요. 결과가 괜찮으면 그때 늘립니다. 개인정보·계약서·미공개 내부 보고서는 넣지 않습니다.
5
기준문서.md 작성하기

탐색기에서 기준문서.md를 클릭해 에디터에서 열고, 아래 구조를 참고해 작성합니다. 처음에는 2~3개 항목만 채워도 됩니다.

# 에이전트 이름 (예: 기술동향 논문 요약)

## 1. 목적
논문과 기사를 읽고 핵심 내용을 정리한다.

## 2. 입력
- data/ 폴더의 텍스트 파일

## 3. 출력 형식
- 핵심 내용 3줄
- 시사점 1줄
- 출처 (제목, 연도)

## 4. 판단 기준
- 연구 배경이 아닌 결과 중심으로 정리
- 한계점이 있으면 반드시 포함

## 5. 하면 안 되는 것
- 원문에 없는 내용 추가 금지
- 연구자 실명 포함 금지
6
Claude 실행하기

VS Code 터미널을 열고 Claude를 실행합니다.

  • 터미널 열기: Ctrl + ` (백틱) 또는 View → Terminal
  • Claude 실행: 터미널에 claude 입력 → Enter
  • 지시 입력:
기준문서.md에 있는 기준대로
data/ 폴더의 파일들을 요약해줘.
결과는 요약_보고서.md로 저장해줘.
7
결과 확인 + 보완하기

생성된 요약_보고서.md를 열어 결과를 확인합니다. 기대와 다른 부분이 있으면 기준문서.md에 빠진 기준을 추가하고 다시 실행하면 됩니다.

  • 결과가 엉뚱하다 → 기준문서.md의 판단 기준 항목 보완
  • 형식이 매번 달라진다 → 출력 형식 항목을 더 구체적으로 수정
  • 내용이 너무 길다/짧다 → 기준 항목에 분량 기준 추가
한 번에 완벽하지 않아도 됩니다. 보완 → 재실행 → 확인이 실제 에이전트 개발 방식입니다.

#!/bin/bash
# 기술동향 에이전트 실행 스크립트
# 사용법: bash run.sh

# 오늘 날짜로 결과 파일명 설정
DATE=$(date +%Y%m%d)
OUTPUT="output/결과_${DATE}.md"

# Claude에게 지시 (대화 없이 바로 실행)
claude -p "기준문서.md에 있는 기준대로 \
data/ 폴더의 파일들을 요약해줘. \
결과는 ${OUTPUT} 로 저장해줘."

# 완료 알림
echo "✓ 완료: ${OUTPUT} 저장됨"
// 터미널에서 실행권한 부여 후 실행

암묵지는 "내가 당연하게 하고 있던 일 처리 기준"입니다.

나는 당연히 아는 기준이라 말하지 않았지만, AI는 그 기준을 모릅니다.
그래서 AI가 이상한 결과를 낼 때는 "AI가 못한다"가 아니라 "내 기준을 아직 안 알려줬다"라고 보는 게 좋습니다.

기준 문서(MD 파일) 만들기

기준 문서는 에이전트에게 업무 기준을 알려주는 파일입니다. VS Code에서 기준문서.md를 만들고 아래 구조로 채우면 됩니다.

항목내용
업무 목적이 에이전트가 처리할 업무
입력 자료어떤 데이터를 읽어야 하는지
출력 형식어떤 형태로 결과를 내야 하는지
판단 기준업무 처리할 때 따라야 할 기준 (핵심)
예외 처리애매한 상황에서 어떻게 할지
하면 안 되는 것확실하게 빼야 하는 것

기준 문서 예시 1 — 회의록 작성

# 회의록 작성 기준 ## 1. 목적 회의 내용을 핵심 중심으로 정리한다. ## 2. 출력 형식 - 회의 개요 (일시, 참석자, 주제) - 결정 사항 - 액션 아이템 (담당자 + 기한) - 보류 사항 ## 3. 판단 기준 - 결정된 내용과 논의 중인 내용을 반드시 구분한다. - 담당자와 기한이 없는 할 일은 액션 아이템이 아니라 보류로 분류한다. - 보고용은 격식체, 팀 공유용은 평서체로 쓴다. ## 4. 하면 안 되는 것 - 확인되지 않은 내용을 결정사항처럼 쓰지 않는다. - 발언자를 지나치게 상세히 나열하지 않는다.

기준 문서 예시 2 — 뉴스 요약

# 뉴스 요약 기준 ## 1. 목적 뉴스 기사를 업무 참고용으로 빠르게 파악한다. ## 2. 출력 형식 - 기사 핵심 요약 3줄 - 관련 기관/기업 - 업무상 참고할 점 - 추가 확인 필요 사항 ## 3. 판단 기준 - 단순 사건 설명보다 업무에 영향을 줄 수 있는 내용 우선 정리 - 추측성 표현은 제외 - 출처 불명확한 내용은 "추가 확인 필요"로 표시 ## 4. 하면 안 되는 것 - 기사에 없는 내용을 임의로 해석하지 않는다. - 확인되지 않은 전망을 사실처럼 쓰지 않는다.

기준 문서 예시 3 — 엑셀 이상값 점검

# 엑셀 이상값 점검 기준 ## 1. 목적 엑셀 데이터에서 확인이 필요한 값을 찾아낸다. ## 2. 출력 형식 - 이상값 목록 - 이상값으로 판단한 이유 - 담당자가 확인해야 할 질문 ## 3. 판단 기준 - 빈 값이 있는 행은 확인 필요로 표시 - 전월 대비 차이가 큰 값은 확인 필요로 표시 - 단, 사유 컬럼에 예외 사유가 있으면 예외로 분류 ## 4. 하면 안 되는 것 - 이상값을 오류로 단정하지 않는다. - 원인을 추측해서 쓰지 않는다.

스킬로 만들기

스킬이란
스킬은 매번 새로 설명하지 않아도 되게 만드는 반복 실행 버튼입니다.

한 번 기준을 잘 만들어두면, 다음부터 같은 일을 할 때 그 기준을 다시 설명하지 않아도 됩니다.

모든 업무를 스킬로 만들 필요는 없어요. 아래 질문으로 판단하세요.

스킬로 만들지 판단하는 질문
이 일을 다음 달에도 또 할 것인가?  /  같은 형식으로 결과물이 나와야 하는가?
매번 같은 기준을 다시 설명하는 게 번거로운가?  /  결과물을 바로 복붙해서 쓰고 싶은가?

2개 이상 "예"라면 스킬 후보입니다.
스킬로 만들 업무스킬 없어도 되는 업무
자주 반복되는 일한 번만 하는 일
매번 같은 기준으로 처리하는 일매번 기준이 달라지는 일
출력 형식이 고정된 일결과물 형식이 유동적인 일
직접 하면 시간이 오래 걸리는 일몇 분 안에 끝나는 간단한 일
스킬 없을 때 — 매번 반복
1회차: 기준 설명 → 실행 → 확인
2회차: 기준 다시 설명 → 실행 → 확인
3회차: 기준 또 설명 → 실행 → 확인
→ 설명 시간이 매번 낭비됨
스킬 있을 때 — 한 번만 설명
1회차: 기준 설명 → 실행 → 스킬로 저장
2회차: 스킬 호출 → 실행 → 확인
3회차: 스킬 호출 → 실행 → 확인
→ 이후 실행은 명령 한 줄

  • 2

  • 4

  • 5

실습 — 기준 문서 + 스킬 설계 20분

지금 할 일
  1. 오전에 고른 업무를 가져온다.
  2. AI가 자주 틀릴 것 같은 부분을 먼저 적는다. (Part A, 4번 칸)
  3. 그 부분의 기준을 말로 써본다. (Part A, 5번 칸)
  4. 기준 문서 초안을 완성한다.
  5. 스킬로 만들지 판단하고 Part B를 채운다.

Part A. 기준 문서 초안 작성 (12분)

기준 문서 워크시트
1. 업무명
AI에게 맡길 업무를 한 문장으로 쓰면?
예) 기술동향 논문 요약 에이전트
2. 입력 자료
AI가 읽어야 하는 자료는 무엇인가?
예) 논문 PDF 본문 텍스트 (민감정보 없음)
3. 출력 형식
결과물이 어떤 형태로 나오면 바로 쓸 수 있는가?
예) 핵심 내용 3줄 + 시사점 1줄
4. AI가 틀릴 것 같은 부분
지금 AI가 자주 놓칠 것 같은 부분은?
예) 연구 배경만 정리하고 결과를 빠뜨림
5. 내가 쓰는 판단 기준
나는 평소 어떤 기준으로 맞고 틀림을 판단하는가?
예) 결과 중심 요약, 한계점 반드시 포함, 출처 연도 명시
6. 예외 처리
애매한 경우 어떻게 처리해야 하는가?
예) 결과가 불분명하면 "추가 확인 필요"로 표시
7. 하면 안 되는 것
AI가 절대 하지 말아야 할 것은?
예) 원문에 없는 내용 추가, 연구자 실명 포함
기준 문서 작성 팁 — 처음부터 잘 쓰려고 하지 않아도 됩니다. AI가 자주 틀릴 것 같은 부분 하나만 적어보세요. 그게 기준 문서의 시작입니다.

멘토 체크 포인트 — 오후 실습 중

수강생이 기준 문서를 못 쓰면 아래 질문을 던진다.

  • 이 업무를 사람이 한다면 무엇부터 확인하나요?
  • 결과물이 좋다고 판단하는 기준은 무엇인가요?
  • 반대로 결과물이 틀렸다고 느끼는 경우는 언제인가요?
  • AI가 절대 하면 안 되는 것은 무엇인가요?

수강생 기준이 모호할 때 이렇게 피드백한다:
"좋은 기준이에요. 다만 AI가 바로 이해하려면 조금 더 구체적으로 써주시면 좋겠어요. 예를 들어 '중요한 내용 중심으로 정리'보다는 '결정사항, 담당자, 기한이 있는 내용은 액션 아이템으로 분리'처럼 써주시면 더 잘 작동합니다."
